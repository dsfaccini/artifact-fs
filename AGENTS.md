# AGENTS.md

Repository-specific guidance for `artifact-fs`.

## Code review rules

- Flag credentials in Git CLI arguments or unredacted logs. Pass credentials through the environment-based helper in `internal/gitstore/credentials.go`. Redact a log field with `auth.RedactLogString`, which replaces each remote it detects with `REDACTED_REMOTE`. Redact an error message with `auth.RedactString`, which replaces the credentials it detects with `REDACTED`. Detection is heuristic, so never log a value known to hold credentials.
- In production code, flag a `model.RepoConfig` in the hydrator, the overlay or `internal/fusefs`. They take `model.RepoPaths`, so `RemoteURL`, which can carry credentials, reaches only the CLI, the registry, the daemon and gitstore.
- Keep adoption's inline-credential check in `WarnAdoptedRemoteCredentials` a warning that names no remote, not a rejection. Adoption stores no URL and never clones, fetches or refreshes. Only Git's lazy fetches and the hydrator's batch fetches use the user's existing remotes. Git's lazy fetch tries each promisor remote in turn, and the hydrator's batch fetch uses the first. The promisor remote is usually `origin`. Flag any other path that persists inline credentials or lets the daemon fetch with them.
- Flag blob bytes converted to `string`. Keep `BlobToCache` binary-safe by streaming `git cat-file --batch` output to disk.
- Keep `GIT_NO_LAZY_FETCH=1` on `git cat-file --batch-check` in `batchResolveSizes`. Removing it turns size resolution in blobless clones into network round-trips.
- Run every Git command that can contact a remote in its own session with the environment `lazyFetchEnv` returns. That covers a clone, `ls-remote`, a fetch, and any command that can lazily fetch missing objects. `runNetworkGit` and `runLazyFetchGitInput` do both. Outside that session, git runs in a background process group, and a terminal prompt stops it until the operation times out. Never set `GIT_SSH_COMMAND` on such a command, or `core.sshCommand` through `-c` or `GIT_CONFIG_*`: either replaces the SSH command that an adopted worktree, a prepared git dir or a conditional include sets. `lazyFetchEnv` sets `GIT_SSH`, which Git runs only when no SSH command outranks it, to the Store's wrapper that runs `ssh -o BatchMode=yes`. The Store writes the wrapper under its temp directory and removes the wrapper on `Close`. Reuse the wrapper only while it and its directory are not symlinks, have mode 0700 and belong to the effective uid. Something can remove the directory, and in the system temp directory another local user can then make one at its path. On Windows `privateToEUID` returns true, so the owner and mode checks do not run there. In `batchModeSSH`, hold `s.mu` only to read or set `sshWrapperDir` and `closed`, never across a file operation. `internal/apfsclone` has no Store. Its `configureGit` gives each git that `apfsclone.Add` and `apfsclone.Git` run its own session and `lazyFetchEnv`'s prompt settings, without the SSH wrapper. Without a terminal, ssh fails a prompt instead of waiting. In a blobless base, `checkout-index` runs one lazy fetch per missing blob. `apfsclone.PostCheckout` runs the post-checkout hook's git in its caller's process group, with neither, as `git worktree add` runs the hook, so the hook can read the terminal.
- Make each file that Git runs or reads for one command or for a Store's life under the Store's temp directory. Those are the SSH wrapper, the hooks directory of the fsmonitor bootstrap, and the files that `RunWithFiles` gives a git for its stdin, stdout and stderr. A pooled `git cat-file --batch` keeps the wrapper's path until `Store.Close`, and the system temp directory guarantees no path stays valid and private that long. `internal/apfsclone` has no Store. Its `refuseConvertingAttributes` keeps a temporary index in a private `os.MkdirTemp` directory, and removes the directory once the check ends. Its `gitWithEnv`, which `apfsclone.Git` runs, its `register` and `PostCheckout`, and slimtree's `worktreeList` give `RunWithFiles` the system temp directory. Keep the per-repo fsmonitor hook out of the Store's temp directory, because Git runs it on every `git status`. The hook is the link `gitstore.FSMonitorHookLink` returns, `<state root>/overlays/<id>/fsmonitor-hook`. Git runs a hook path with a character from `gitShellMeta` through `sh -c`, which splits it, so for such a link path the hook is the script `<git dir>/hooks/artifact-fs-fsmonitor`. The hook is the script also when `privateAncestors` finds that another user can write or rename the state root or a directory above it. `ReleaseAdoptedWorktree` unsets either path. `newCore` sets the temp directory with `Store.SetTempDir`: `<state root>/config/tmp/daemon` for `daemon.New`, `<state root>/config/tmp` for `NewController`. `ensureStateRoot` checks `config/tmp`. A Store without `SetTempDir`, as in tests and benchmarks, uses the system temp directory.
- A Store runs no git once `Close` has begun. Start each git of a `Store` through `Store.runWithFiles`, or, for a pooled `git cat-file --batch`, with the environment `lazyFetchEnv` returns. Both call `checkOpen`, which returns `errStoreClosed` after `Close`. `BootstrapCleanIndexForFSMonitor` calls it before it takes `index.lock`. Never turn `errStoreClosed` into a `gitCommandError` or an error rebuilt from stderr, so a caller can match it with `errors.Is`. `Service.Close` closes the Store also while a runtime whose stop failed keeps its FUSE server and hydrator, and while workers that outlived `endWorkers` run. Otherwise their gits keep running, and making files in `config/tmp/daemon`, after `Service.Close`. `Store.Close` terminates the pooled processes and removes the SSH wrapper. It neither waits for nor cancels a git that runs to completion and started before it. That git's context bounds it. `TestStoreRunsNoGitAfterClose` and `TestBatchPoolStartsNoGitAfterClose` pin the refusal.
- Run each git that sets `WaitDelay` and runs to completion through `gitstore.RunWithFiles`, never with a pipe for a stream. `ConfigureCancelableCommand` sets `WaitDelay`. os/exec copies a stream that is not an `*os.File` through a pipe. When another process still holds the pipe's write end, `WaitDelay` after git exits, os/exec fails a git that exited 0 with `exec.ErrWaitDelay`. The ssh ControlPersist master of a lazy fetch holds stderr. A child that another goroutine forked holds every stream until it execs (golang/go#22315). `RunWithFiles` unlinks a file for each stream before git starts, and reads the files once git exits. It hands git an `*os.File` the caller set as it is, so the post-checkout hook that `apfsclone.PostCheckout` runs still reaches the terminal. It gives one writer set as both stdout and stderr one file, as os/exec gives it one pipe, so the streams keep their order. It passes the stdout file to a parser only once git exits 0, because a git that failed, as on a full disk, can leave its last line cut. Keep pipes only for the pooled `git cat-file --batch`, which logs each stderr line as git writes it. `TestGitSucceedsWhileAnotherProcessHoldsItsOutput` pins gitstore's commands with `gittest.HoldGitOutput`.
- Write each file that a process may exec, in production code and in tests, with `execfile.Write`, as `replaceExecutable` and `batchModeSSH` do. A fork while `os.WriteFile` holds the file open hands the child its write descriptor until the child execs (golang/go#22315). An exec of the file in that window fails with ETXTBSY. Git then fails, or retries an fsmonitor hook as v1 and misreads the v2 answer. `execfile.Write` holds `syscall.ForkLock` for reading, which every fork takes for writing.
- Release every flock with `LOCK_UN` before you close its file, as `releaseDaemonLock`, `unlockStats`, apfsclone's `unlockFile` and slimtree's `state.release` do. A flock belongs to the open file, and a child that another goroutine forked holds a copy of each descriptor until it execs (golang/go#22315). Closing the file alone then keeps the lock until the child execs. Pin a release with `gittest.HoldForkedCopies`, as `TestCloseReleasesTheDaemonLockAForkedChildHolds` does.
- Empty `config/tmp/daemon` only in `daemon.New`, while it holds the daemon lock, as `emptyDaemonTempDir` does. Never sweep the rest of `config/tmp`: a CLI's Store uses it while the daemon runs, and a process ID cannot tell a live Store from a dead one across PID namespaces.
- Flag a `FetchNonInteractive` fetch without the explicit refspec `refreshTarget` returns. A `--prepared-gitdir`'s configured refspec can name every branch, and with `--depth` each new branch then arrives with its whole history. A clone's configured refspec names `--ref` and can miss the fetch ref, such as a tag.
- Flag a `ComputeAheadBehind` that compares HEAD with a ref other than the tracking ref `refreshTarget` returns.
- Stop a Git command only with `terminateCommandProcessGroup`, as `ConfigureCancelableCommand` and `batchCatFile.terminate` do. It sends the command's process group `SIGTERM`, then `SIGKILL` after `GitCommandWaitDelay`. On `SIGTERM` Git removes the lock files it created, such as `index.lock` or `objects/maintenance.lock`, but only once it installed the handler that does so, microseconds after it created its first lock file. A Git that `SIGTERM` hits in that window, or that `SIGKILL` ends, leaves the lock, and every later Git that takes the lock fails or, for maintenance, skips without a word. Never delete a Git lock file in code: one that a running Git holds looks the same. The git that runs apfsclone's post-checkout hook shares its caller's process group, so its cancel sends `SIGTERM` to that git alone.
- Run each git command that writes the git dir and contacts no remote through `runGitWrite`, `runGitWriteWithEnv` or `runGitWriteInput`: git config and every command that writes config, such as `init`, `remote add` or `branch --set-upstream-to`, and `update-ref`, `symbolic-ref` and `update-index`. Run a read-tree, which writes the index and can lazily fetch, through `runNetworkGitWrite`. Their `writeContext` starts no write once its context ended, and lets a running write outlive its context's end by at most `defaultWriteGrace`, plus up to `GitCommandWaitDelay` for the stop that follows, which finds Git's handler installed. `hash-object -w` takes no lock and stays cancelable. Keep cancellation for every other command that can contact a remote, such as a clone, a fetch, `ls-remote` or a lazy fetch, because it can hang. A cancel that lands in the microseconds after such a command creates its first lock can still leave the lock. `TestACanceledLocalWriteRunsToItsEnd` and `TestACanceledFetchStops` pin both.
- Flag a child process whose `Cmd.Dir`, program, or interpreter lies on a mount the same process serves. On Linux the forking thread waits in vfork holding its P with signals blocked, so a GC stop-the-world, or forks holding every P, stops the FUSE server that the child's chdir or exec waits on. Root-package tests start a process in a mount directory through `commandIn` with a non-empty dir.
- Run every step of one rollback under one `Store.rollbackContext`. A rollback outlives its caller's cancellation. `gitstore.RollbackBound` bounds it, and `TestDrainOutlastsTheRollbackOfACanceledPreparation` keeps that bound below the daemon's `drainTimeout`. A git command that reports failure can still have landed. So a rollback leaves the index when HEAD already resolves to the new commit, and undoes a forward read-tree that moved the index.
- Add a blob cache file only with `blobcache.Stage` and `blobcache.Install`, and remove one only with `blobcache.Evict`. `Install` and `Evict` update the counters `status` reads under the cache's `stats` flock. A direct write or unlink leaves the counters wrong until the next mount or `evict-cache` recounts them.
- Record each open of a cached blob that serves the mount with `blobcache.RecordRead`, as `OpenHydrated` and `ReadBlob` do. A read through the file an open returned records nothing more, as `FileHandle.read` on `cacheFile` does. `evict-cache` orders blobs and applies `--older-than` by the access time `RecordRead` writes. Identify a verified cached blob only by its size, modification time and file identity, as `sameFileInfo` and `Blobs.open` do. `RecordRead` changes its access time and its change time.
- Resolve a slimtree command's worktree argument only with `state.Home.Resolve`. While `./foo` exists, it refuses the name `foo` of a worktree other than `./foo`, so `slimtree rm foo` never removes another directory than the one the user sees. It checks `./foo` only, no deeper path. Compare a path that the user or a record spells with a path that git prints only with `state.SamePath`: on a case-insensitive volume, the Mac's default, git prints a directory's case on disk. `SamePath` follows no symlink, so a symlink at a worktree's path never stands for the worktree it points at.
- Keep slimtree's `new` and `rm` recoverable. `new` records only a complete worktree. On a failure, `rollback.run` removes the worktree when git registers it, the directories above it that `git worktree add` made, and the branch that `new` made, with the tracking keys that `--track` added. It deletes the branch only while the branch still points at the commit `new` made it at, and runs past a cancellation. `new` refuses a path where git already registers a worktree, and a path whose record directory exists, which can hold an earlier worktree's state. Another process can still register the path outside the global lock, so `rollback.run` removes a registration only on `new`'s branch, and on a branch that existed only when `Add` reports that it registered the path. `new` runs the post-checkout hook after it writes the record and releases the global lock. A failed hook leaves the worktree and its record, as `git worktree add` keeps its worktree. A failed artifactfs `new` also puts the gitfile back and removes its record directory, in `undoArtifactFS`. `rm` never deletes a branch. It writes the archived record with `state.Home.Archive` before the recovery ref that `Archive` returns, so an archived record names the repository of every recovery ref.
- Start an artifactfs worktree's daemon only through `serve`. `startDaemon` runs `slimtree daemon` from the copy `runtimeCopy` writes, in its own session, in the record directory. `daemonEnv` drops `localGitEnv` and the `GIT_CONFIG_KEY_*` and `GIT_CONFIG_VALUE_*` variables. It sets `ARTIFACT_FS_ROOT` to the state root, and on macOS `ARTIFACT_FS_FUSE_BACKEND` to `fskit`. `startDaemon` takes the start token right after the start. Until `serve` writes the record, a failure stops the daemon with `launchedDaemon.stop`: SIGTERM, SIGKILL after `daemonTermWait`, a reap bounded by `daemonKillWait`, then an unmount of the mount a killed daemon leaves. Once the record is written, the daemon keeps serving. A failure that leaves the daemon or its mount wraps `errStillServed`, and `new` then removes nothing.
- Record another mount identity for an artifactfs worktree only in `healRemount`, while the recorded daemon runs, its status reports the worktree mounted, and `checkMounted` finds the worktree and its git dir through the mount. After an external unmount, the daemon mounts again with a new identity. Refuse every other mount whose identity is not the recorded one. `list` records nothing: it reports such a mount as unknown.
- Signal a process that the running slimtree did not start only with `mounts.Signal`, which sends only while the PID's start token matches and the process has not exited. Signal its own child through the child's `os.Process`: no other process takes the PID until slimtree reaps the child. Take a start token only from `mounts.StartToken`, which reads the start time that fork sets and exec keeps. Never identify a process by its argv: right after exec, Linux shows an empty cmdline. Tell that a child exited only from its wait status. Before you signal the PID that `daemon.Running` returns, match it with the start token recorded when that daemon started: for an instant after a new daemon takes the lock, the lock file names the previous daemon. Unmount a worktree only with `mounts.Unmount`, which unmounts only after the mount's identity matched. Run each external command of `internal/slimtree/mounts` through `run`, which runs the command in its own session and returns at most `stopGrace` after `commandTimeout` or a cancel, even when the command has not exited.
- Normalize paths only with `model.CleanPath()`. Do not add local wrappers.
- Use the canonical `model.*` interfaces for registry, git store, snapshot, overlay, and hydrator access. Do not add subset interfaces around them.
- In production code, assert each implementation of a `model.*` interface with `var _ model.X = (*T)(nil)`. Test fakes need no assertion.
- Add a method to a `model.*` interface only when production code calls the method through the interface.
- In production code, only `internal/daemon` holds a concrete snapshot, overlay or hydrator type, because it opens and closes them. Tests may build concrete stores.

## Architecture

- `cmd/artifact-fs` and `cmd/slimtree` are the only binary entrypoints. `cmd/slimtree` runs `slimtree.Main` in `internal/slimtree`.
- `internal/cli` runs the `daemon` command on `daemon.Service`, the `fsmonitor-hook` command on `daemon.FSMonitorHook`, the hook link on `daemon.FSMonitorHookByID`, and every other command on `daemon.Controller`, except the `gc`, `doctor` and `prefetch` stubs. Only `daemon.Service` mounts.
- `cli.Main` runs the hook link when `gitstore.ParseFSMonitorHookLink` accepts the program name, and `cli.Run` dispatches `fsmonitor-hook` before it builds the CLI. `slimtree.Main` hands the hook link to `cli.Main`, and the hidden `daemon` and `fsmonitor-hook` commands and `afs <command>` to `cli.Run`, before it builds slimtree's CLI. The daemon links the hook to its own binary, so both binaries answer the hook. Git runs the hook on every command that reads the index, so the hook opens no `daemon.Controller`.
- `internal/daemon` owns repo lifecycle: registry sync, snapshot publish, overlay reconcile, FUSE mount, watcher, refresh loop.
- `internal/fusefs` is the merged view and writable filesystem layer.
- `internal/gitstore` is the performance-sensitive git wrapper; most easy-to-break invariants live there.
- `internal/snapshot` and `internal/overlay` are persistent SQLite-backed stores.

## Runtime contracts

- `ARTIFACT_FS_ROOT` is the state root. Each repo mounts at the path its registration stores: `add-repo --mount-root`, default `<state root>/mnt`, plus the repo name. `artifact-fs daemon --root` changes no registered repo's mount path.
- `add-repo` is one-shot by default: register repo, clone blobless, build the initial snapshot, then exit. It does not mount FUSE or start background goroutines.
- `add-repo --async` only registers prepare state. The daemon mounts a gated placeholder, prepares clone/fetch and snapshot in the background, then opens the gate and starts watcher/refresh.
- `config_version` identifies a registered config, and only a new registration changes it. Use it as the only token that a config is still current.
- `prepare_request` identifies the latest prepare request, from `add-repo` or `prepare`. Write a preparation's outcome only while its `config_version` and its `prepare_request` are both current. Write the acquisition receipt while its `config_version` is current; the receipt belongs to the config, not to the request.
- A prepare request never unmounts a repo. The daemon prepares an async repo again behind its runtime's gate. The CLI prepares a sync repo while the daemon keeps serving it.
- Refresh settings and the kept-generations warning threshold are not part of a repo's prepare identity. `set-refresh` and `set-warn-kept-generations` change neither token.
- `daemon` is long-running: it mounts registered repos and starts watcher, refresh, and hydrator workers.
- The daemon holds a flock on `<root>/config/daemon.lock`. A second daemon on one state root fails. CLI commands probe that lock to learn whether a daemon runs.
- The registry carries every request from the CLI to the daemon. The control socket only wakes the daemon.
- Only the daemon writes `repo_runtime`. It writes the record at every transition and every retried failure. `status` reads that record and the stores, never daemon memory.
- `unmount` and `remount` write an intent to `enabled` and `mount_request`, then nudge `<root>/config/daemon.sock`. They wait until `repo_runtime` echoes the request.
- One sync loop serves every repo. Bound every per-repo step it runs, so one repo cannot stall the others. A mount waits at most `mountTimeout` through `fuse.MountContext`. Start a stop with `Service.stop`, which runs it off the loop; the loop never waits for a stop. The loop never waits for a repo's prepare lock either, which a preparation can hold for up to its timeout.
- Unmount a repo only through `startUnmount`. It runs one unmount per repo on its own goroutine, because `unmount(2)` can hang on a dead FSKit volume. A stop runs whole as the repo's unmount, from its unmount through its drain, so it unmounts without a second `startUnmount`. Wait only for an unmount you started, and at most `unmountTimeout` plus `unmountReturnSlack`. `Service.unmount` is the exception: `Close` waits through it for any stop of the repo, at most `stopWaitTimeout`. A stop whose unmount fails keeps the runtime serving through `keepServing`, so a live daemon's mount stays up. A stop also fails when its drain times out, or when an earlier unmount of the repo has not returned. When a stop of `Close`'s fails or does not return, `Close` cancels the runtime's context with `endWorkers`. It then waits for the runtime's workers within the same `stopWaitTimeout`. The process exits after `Close`, and a worker that outlived it would still touch state that a caller removes, while every git of the closed Store fails. `Close` leaves the runtime's FUSE server and hydrator, which are not workers, to the process exit.
- `Service.Close` closes the Store only after every preparation's rollback ended. The closed Store refuses every git, so a rollback that runs later leaves the index at the new commit and HEAD at the old one. When every runtime's workers ended, `Close` waits for the preparations. Otherwise a preparation under `Start`'s context, or one among the workers that outlived their wait, can still run. `Close` then calls `endPreparations`, which cancels each preparation and waits at most `gitstore.RollbackBound`. `TestCloseWaitsForARollbackAfterWorkersOutliveTheirWait` pins the wait.
- Wait at least `daemon.ExitBound` after you send SIGTERM to a daemon that serves one repo, before you send it SIGKILL or report that it did not exit. `ExitBound` adds `stopWaitTimeout`, `gitstore.RollbackBound` and `exitSlack`, which bound `Service.Close` and what follows it for one repo. It leaves out the time `Start` needs to finish a sync pass that runs when SIGTERM arrives. A SIGKILL during `Close` leaves a mount the daemon did not unmount, which no FUSE server answers. On FSKit, `unmount(2)` of such a volume can hang. `Close` stops repos one at a time, so a daemon that serves more repos can take longer. slimtree's `launchedDaemon.end` and `stopDaemon`, which `stopWorktree` and `resumeWorktree` call, wait `daemonTermWait`, which defaults to `ExitBound`. `TestDaemonTermWaitOutlastsTheDaemonsExit` pins the default.
- Build a runtime only with `startRuntime`. Mount it only with `attachMount`, which checks every mount precondition. A dead mount whose unmount failed blocks a new mount while the mount table lists its mount point.
- Mount with the runtime's op context. Only a stop cancels it, never the end of `Start`'s context. A stop unmounts first, then cancels the op context, which cancels the ops in flight, then closes the runtime's stores and its `git cat-file --batch` processes.
- Unmount a mount the daemon did not make only when the daemon process before this one ran the repo or still claimed a leftover there, and `ownsLeftover` matches the mount, or when it is an abandoned mount the fuse library failed to unmount. Leave every other mount alone. Record each repo a clean shutdown unmounted as stopped, so the next daemon claims none of its own mounts. Every `repo_runtime` record carries the daemon's leftover claim on the repo in `claims_leftover`, so a claim the daemon has not released outlasts a restart and leaves the reported state alone. A disabled repo releases its claim through `releaseLeftoverMount`, backed off like a mount. A running daemon ends a removed repo's claim at its next registry sync.
- Back off a retried mount, HEAD reconcile or remote refresh with `retrier`. `status` shows each failure with its next attempt.
- `gitstore.Store.CloneBlobless` already populates the git index with `read-tree HEAD`; be careful about extra index resets because they can discard staged state.

## Code conventions

- Keep merged directory logic in `Resolver.readdirTypedAt`. `ReaddirSnapshot` and `ReaddirTyped` only choose the generation.
- Resolve a path as its parent's listing shows it. `Resolver.resolvePath` resolves a directory that only overlay entries below it imply, as `mergeChildren` lists it.
- Record each change to a directory's listing with `Resolver.listingChanged`, after the overlay change succeeds, as `Engine.Create` and `Engine.Unlink` do. Git's untracked cache trusts a directory whose stat data has not changed. A record made before the change lets a reader see the new time with the old listing. A directory that only overlay entries imply appears with the first entry below it and vanishes with the last, which changes its parent's listing too. Record those parents through `absentDirsAbove` in every op that makes or moves an entry: `Engine.Create`, `Engine.Mkdir`, `Engine.Symlink`, `Engine.Rename` at both paths, and the recreating `Engine.Write`. An op through the inode of a directory a switch removed makes an entry there. An unlink or rmdir leaves a delete marker that keeps the directory implied. `Resolver.SwitchGeneration` records its changes with `listingsSwitched`, every listing when `SwitchedPaths` is `Unknown`. The switch pass takes them with `Engine.SwitchedListings`, together with the generation it compares at, in one hold of the transition read lock, as a switch sets both in one write hold. The pass invalidates each directory among them that the kernel holds, because no identity it compares holds a directory's times. It skips one whose last reply came at that generation and so carried the new times, so a record taken with an earlier generation would be lost. Forget the records of a directory an op removes with `Resolver.dirsRemoved`, as `Engine.Rmdir` and `Engine.Rename` do.
- Call `requireAbsent` in `Engine.Create`, `Engine.Mkdir` and `Engine.Symlink` before they make the name. The kernel can send CREATE, MKDIR or SYMLINK for a name that appeared after its lookup missed, such as after a HEAD change. `Engine.Rename` replaces its target, so it does not call `requireAbsent`.
- Run every preparation through `core.prepare`. Express a new caller's differences as a `preparation`, not as another pipeline.
- Give each piece of a repo's state one guard. Take that guard wherever the daemon or the CLI changes the state. The repo's prepare lock, `withRepoPrepareLock`, guards the git dir's refs, HEAD, index and config: every Git command of the daemon and the CLI that writes them runs under it. `core.prepare` holds it through a preparation and its `complete`, the refresh loop through its fetch and its ahead/behind count, `Controller.FetchNow` through its fetch, and `Controller.RemoveRepo` through an adopted worktree's release, before the config lock. A regular repo's removal writes no git config, so it does not wait for a preparation. The daemon's mount check, `mountRepo`, and the status optimization config write of a mount that `retryMount` retries run on the sync loop, so each takes the lock only while it is free. A mount check that finds the lock held skips the repo and records no failure, and the next sync checks the repo again. So does a mount check that a registration or a prepare request newer than the sync's listing supersedes, because the next sync lists that request as current. A config write that finds the lock held runs at a later sync, once the lock is free. A preparation, a refresh and a fetch command fetch into the same tracking ref, and two fetches that overlap fail each other's ref update. Git commands a user runs in the work tree take no lock, and the HEAD watcher follows them. The repo's config lock, `withRepoConfigLock`, guards the repo's config version: `Controller.AddRepoWithOptions` and `Controller.RemoveRepo` set or remove it under the lock, and `withCurrentPrepare` checks it under the lock around a preparation's publish and prune. A runtime's `headMu` serializes its HEAD reconciles, its activations and its prunes, `Resolver.switchMu` its generation switches, `Service.mu` the `repoRuntime` fields marked as guarded by it, and `Service.recordMu` its `repo_runtime` writes.
- When you add a writer of snapshot generations, never assume a lock keeps the other writers out: they have no single guard yet. `publishPrepared` publishes them under the config lock, and `reconcileHEAD` under `headMu` alone.
- Take the daemon's locks in this order: the prepare lock, then `headMu`, then the config lock, then `Service.mu`. `headMu` comes before `Resolver.switchMu`, which comes before the overlay's `reconcileMu`, the resolver's `transition` and the overlay's `Store.mu`, in that order. `Service.recordMu` comes before `Service.mu`, and `Service.mu` before `ReadyGate.mu`. The switch pass can run under the prepare lock or `headMu`, and takes the FUSE locks after them, in the order of the FUSE lock bullet. Take nothing while you hold `repoRuntime.retiredMu`. SQLite's write locks come last: a write transaction takes its database's write lock at BEGIN, and waits at most the 5 s busy timeout for it. Never take the prepare lock while holding `headMu`, because that inverts `activatePrepared`'s order.
- Before you add a daemon goroutine that acts on a repo, list the steps that can run beside it: a first preparation, a re-prepare while the runtime's workers run, a CLI preparation of a sync repo, the daemon's mount check (`mountRepo` through `core.prepare` to `startPreparedRuntime`), an activation's switch and its pass, a HEAD reconcile, the refresh loop, a fetch command, the hydrator's fetches and `git cat-file` processes, a remove-repo, and a stop. For each step, take the guard of the state both touch. Skip only on a state the step sets under the guard you hold, as `reconcileHEAD` skips a runtime that `rt.stopping` marks under `s.mu`, which `stopRuntime`'s `keepServing` clears and signals again once the stop fails. A state check outside the guard races, so use one only to refuse early, as `Controller.FetchNow` does before it waits for the prepare lock. Read the state your write depends on after you take its guard, and skip the write when that state moved, as `completePreparedRuntime` checks `samePrepare` in the `s.mu` hold that opens the gate. A guard that only serializes two writers does not order them. Take the prepare lock holding no other lock, with a context a stop cancels, as `refreshLoop` does. Bound what you run under the prepare lock, as `fetchTimeout` bounds a refresh and a fetch command, because every preparation and refresh of the repo waits while you hold it. Once your context has ended, return without recording a failure, as `refreshLoop` and `headReconcileLoop` do. Pin each pair that shares state with a hook test. Pin a pair of steps that fetch under the prepare lock as a row of `TestFetchesWaitWhileAnotherStepHoldsThePrepareLock`: its holder holds the lock at a hook, and the row orders the other step by its `lockBusy` report, never by a collision.
- Normalize a repo config only in `normalizeRepoConfig`, before the registry stores it. Readers trust the stored config: never re-default or re-resolve a field after reading it.
- Parse a ref only with `model.BranchName` and `model.CanonicalRef`. Keep two hand parses in `internal/cli`, because those helpers would change their meaning. Keep the deprecated `add-repo --branch` alias dropping one leading `refs/heads/` and storing the rest under `refs/heads/`. `--branch x` and `--branch refs/heads/x` both store `refs/heads/x`, and `--branch origin/x` stores `refs/heads/origin/x`. Keep `list-repos` shortening only a `refs/heads/` ref and showing every other stored ref in full.
- Keep the watcher polling `HEAD` and the ref it names, loose or in `packed-refs`. Read a linked worktree's `refs/bisect/`, `refs/worktree/` and `refs/rewritten/` refs from its own git dir. Read every other ref from the common dir. Preserve the branch-switch, packed-ref and linked-worktree behavior that `internal/watcher/watcher_test.go` and `internal/watcher/linked_test.go` cover.
- After each HEAD reconcile that succeeds, rebase the runtime's watcher with `Poller.Rebase`, then resolve HEAD again, as `servesHEAD` does. Reconcile again while that HEAD differs from the served HEAD. Rebase after the reconcile's read, never before it. A poll compares only with the last poll or rebase, so HEAD can move to a state no poll saw and back without a signal. Skip the check while the runtime stops, is replaced, or has a required commit. `reconcileHEAD` changes nothing then, so the check would loop forever.
- Keep `ResolveHEAD` reading HEAD's ref before and after HEAD's commit until both reads agree. A HEAD write between two reads otherwise pairs one state's commit with another state's ref. A switch away and back between the two ref reads still returns a mixed pair. `servesHEAD` serves HEAD again once the switching stops.
- The overlay stores deletes as SQLite entries with `kind='delete'`; there is no on-disk whiteout file layer.
- Compare an overlay entry's mode with a base mode only in `overlayEntryMatchesBase`, which ignores `ignoredModeBits`: group and other write, which the umask of each process that writes through the mount decides. Every other bit counts. An entry matches only a base of its own type, so a file entry never matches a symlink whose target is the file's content. A reconcile that drops a file entry whose mode differs from the base's in those bits logs nothing, because Git compares only a regular file's owner execute bit.
- SQLite is `modernc.org/sqlite` in WAL mode via `internal/meta`.
- Every `BeginTx` without `sql.TxOptions{ReadOnly: true}` takes the write lock at BEGIN, because `meta.OpenDB` sets `_txlock=immediate`. SQLite fails a read transaction's upgrade to a write at once with SQLITE_BUSY. Begin a transaction that only reads with `ReadOnly: true`, so it never waits for a writer.
- Before a call returns, wait for every git it started beside its main command, as the stop func of `startRemotesForLogging` does. A git that outlives its call can write into a test's `t.TempDir()` while cleanup removes it. A pooled `git cat-file --batch` outlives its call by design, until `Store.Close`. `TestFetchStartsBeforeAndEndsAfterItsRemoteLookup` pins the wait with a fake that records its PID and ignores SIGTERM.
- Change a store's schema only by appending a migration to its `migrations` list. `meta.Migrate` records each applied migration in `PRAGMA user_version` and never reruns it. An edit to a shipped migration never reaches an existing database. With each new migration, add a fixture at its `user_version` to that store's `migrate_test.go`. That fixture fails the tests when a later edit changes a shipped migration.
- The FUSE adapter calls only `Engine` methods, one per operation. Do not reach into `engine.Overlay`, `engine.Hydrator`, or the `Resolver` from the adapter.
- Hold no lock while a blob hydrates. An `Engine` method that needs base content takes a `*Blobs` and returns a `notHydratedError` when a blob is missing. `Engine.Do` then hydrates with no lock held and reruns the method.
- Open every blob an `Engine` method copies before it changes anything. A directory rename is the one exception: it opens each blob as it copies it, so it may already have promoted some directories and copied some files, all with base content, and the rerun completes it.
- Take the FUSE locks in this order: `handleOps`, `DirHandle.mu`, the resolver's `transition`, `ArtifactFuse.mu`, `FileHandle.mu`.
- Release each FUSE lock with `defer`, or hold it only around code that cannot panic. The fuse library recovers a panic in an op and keeps serving, so a lock left held blocks every later op.
- Wrap an operation error's cause with `%w`, and let `toErrno` map it for the kernel. Do not return `syscall.EIO` for a failure that carries an errno.
- Return every FUSE op's error through `opError`, as `shared` and `exclusive` do. The kernel receives an error with no errno as EIO, and the fuse library logs only the error's text. `opError` adds the op's inode and path to such an error. It leaves an error that carries an errno unchanged.
- Record each `repo_runtime` transition in one write. Apply a failure and the state it leaves in one update, as the `updates` of `recordFailure` do. `status` can read between two writes.
- Record a mount as soon as `attachMount` has it, in the write that clears the mount's earlier mount and serve failures. The mount point serves already. The fuse library serves before the mount call returns, so `status` still trails the mount table briefly. E2E tests wait for both with `waitForMount`.
- Start the unmount of a dead mount in the `s.mu` section that marks the mount failed, as `joinMount` does. `MountedFS.Unmount` unmounts the mount point by path, whichever mount holds the mount point then. A retry then finds that unmount running and leaves the mount to the next sync, so the unmount never reaches a remount.
- Log in the overlay's change log every path whose content, type or owner execute bit in the merged view changes, because Git trusts each index entry the fsmonitor hook does not name. The triggers log the overlay's writes. For a switch between two generations, `Resolver.SwitchGeneration` diffs them with `fusefs.SwitchedPaths`, and `ReconcileChecked` logs each changed path that no overlay entry covers and records the new generation as served, in one transaction. `Service.switchGeneration` logs again the paths its reconcile logged, which `ReconcileChecked` returns, with `Store.LogSwitched` after the kernel invalidations, and on FSKit once more after `fusefs.CacheTTL`. Never log a path whose entry the reconcile dropped because the new base matches it, such as a committed file's. Only the path's times and its group and other write bits changed, which Git does not compare as content or mode. A path the hook names whose stat data the index does not match counts as changed until a refresh. `git diff-files` then reports it, and `git stash create`, which `git merge` runs, fails. A runtime's first switch, from generation 0, logs nothing: its gate held every op, so nothing Git saw changes, and a new instance would discard the clean-index bootstrap's token. A runtime start diffs from `Store.ServedGeneration`, and prunes only after its reconcile records the new generation, so a start that fails leaves the served generation to the next. `startPreparedRuntime` passes the diff to its reconcile, and `mountAsyncRepo` to `Store.MarkServed`. The diff is `Unknown` when the old generation has no root entries, as after a prune or before migration 3 recorded one, when a listing fails, or once it holds more paths than `Store.SwitchedPathsLimit`, the store's cap plus its entries, where it stops its walk. The overlay database then gets a new instance, as it does past the store's cap of paths that no entry covers, `Store.MaxSwitchedPaths`, which `overlay.New` sets to `model.MaxSwitchedPaths`. Tests lower the cap on the store, not the constant. Renew the instance in no other case: a rescan makes Git read every file whose stat data it cannot trust, and each mount numbers its inodes anew.
- Switch a runtime's generation only through `Service.switchGeneration`. It sends the kernel the invalidations the switch needs through `MountedFS.InvalidateChanged`. On every backend, `InvalidateChanged` also unmaps each path the switch removed, and closes each overlay file that a handle that is not detached holds and the overlay no longer names for the handle's path. That close skips detached handles, whose pinned copy no entry names, and holds `handleOps` shared, so no unlink or rename is between `pinOpenFiles` and `detachOpenHandles`.
- Record a generation's times with `fusefs.RaiseMtimes` before readers resolve against it, as `Resolver.SwitchGeneration` does, and `recordBaseTimes` at a runtime start. A start that skips it records no commit time for the generation, so a later start raises nothing from it. Compute a base entry's mtime and ctime only with `baseTime`, which `Engine.Attrs` and `readdirAttrs` share, so a getattr and a listing report the same raised mtime.
- Send a switch pass only while the repo's gate holds no ops. The kernel can hold a directory's lock while a lookup there waits at the gate, and the pass's entry invalidations wait for that lock, so the pass and the lookup would wait on each other. `switchGeneration` starts its pass with `ReadyGate.StartPass`. While the gate holds ops, one of the runtime's workers sends the pass once the gate opens or fails. A `Reset` during a pass holds ops only once the pass ends. An activation checks that its prepare request is current and opens the gate in one `s.mu` hold, in `activate`, which `switchGeneration` runs after the resolver switch and before the pass. A newer request's reset then lands before the check, which supersedes the activation, or after the open. An activation holds the runtime's `headMu` from before its clean-index bootstrap until it records the served HEAD. HEAD can move after the preparation read it, and a HEAD reconcile then serves the moved HEAD at another generation, after which the watcher signals nothing. So the activation resolves HEAD again, and when a runtime that follows HEAD serves it, the activation keeps the generation and served HEAD it serves. It then switches to the generation it serves, so its pass still runs. It runs the bootstrap, which matches the index with the preparation's generation, only when it switches to that generation. The activation sets the runtime's prepare state and served HEAD, which every record reads, only after the pass.
- Bump `cacheCloses` in every function that closes other handles' cached files while ops hold `handleOps` shared, as `closeCachedFilesForPath` and `closeReconciledFiles` do. Bump it while the function collects the handles under `ArtifactFuse.mu`: it cannot see a handle that registers later. An open reads `cacheCloses` before `Engine.OpenFile`, and opens again when the count moved before `addFileHandle`. After `openAttempts` opens, `addFileHandle` registers the handle without its file. Record the blob an open serves in `InodeRef.PageBlob` only in `addFileHandle`, for the attempt that registers, under the `ArtifactFuse.mu` hold of its count check. A registration without its file records an empty blob. An attempt that a close overlapped otherwise records a blob no reply sent, and the next attempt tells the Linux kernel to keep pages that can hold other bytes.
- Never wait on a kernel invalidation inside an op or while holding a lock an op takes. The kernel can hold a directory lock while it waits for that op's reply, and the invalidation waits for the same lock.
- Never wait on a kernel invalidation while the repo's gate holds ops. The kernel can hold a directory's lock while a FUSE op there waits at the gate, and an invalidation of that directory waits for the lock. `switchGeneration` starts its pass only through `ReadyGate.StartPass` for this reason.
- Keep a path's inode number while the path exists and keeps its type. Git compares `st_ino`, so a new number marks a file changed. A FORGET leaves the path's `pathToInode` mapping in place, dormant, for the next lookup. Unmap a path only when it stops existing or changes type. A path stops existing at an unlink, rmdir or rename over it through the mount, or at a HEAD change that removes it.
- When a reply or the switch pass finds that a path's type changed, retire the inode the kernel holds for the path with `retireRetypedLocked`, as `allocInode`, `setReported` and `invalidateChanged` do. Linux and the macFUSE kernel extension fail every op on an inode whose type a reply changes. A getattr reply does not rebind the name, so `setReported` leaves the name's entry and the inode in `retypedNames` for the next switch pass to invalidate.
- Check the type under the transition read lock before a write or an attribute change through an inode reaches its path, as `Engine.Write` and `Engine.SetAttributes` do. Return `errTypeChanged` and change nothing when the path has another type. A switch can land before the pass or a reply retires the inode. Close the handles' cached files only after that check, as `Engine.SetAttributes` does through `openFiles`. Never close them after a refusal: `writeFile` and `setInodeAttributes` skip that close on `errTypeChanged`. A handle whose cache a refused change closed reads nothing once its inode is retired.
- Unmap a path that a HEAD change removed with `unmapPathLocked`. It keeps an inode the kernel still holds in `unmapped`. When the path comes back as `InodeRef.returnsAs` accepts, map it back to that inode with `mapLocked`. Otherwise retire the inode with `retireLocked`, so its handles never reach the path again. Retire it also when another inode takes the path, and when an op through the mount removes it.
- Decide an unmapped inode the same way before a reply records a new identity on it, as `allocInode` and `setReported` do, and before an unlink or a rename reaches its path, as `settleUnmappedBelow` does. Otherwise the switch pass compares the path with an identity the inode never held, and maps the path back or retires the inode wrongly.
- Run `CreateFile`, `LookUpInode` and `ReadDirPlus` through `sharedUnlessUnmapped`, and make each return `errUnmappedPath` while it holds handleOps shared and a path it replies for holds an unmapped inode. `LookUpInode` does so only once it found the path, and `CreateFile` also when its path maps to an inode. Each can retire that inode, so it must not run while a write through the inode reaches the path.
- Answer `GetInodeAttributes` for a retired inode, or for one whose path is away, with `heldAttrs`. Linux fetches an open file's attributes before a read once they expire, and fails the read with any error that getattr returns.
- Mark a handle `pinned` only with `markPinned`, after an unlink or a rename over its path committed. A write through a detached handle, or a setattr of a retired inode, reaches the handle's file only when the handle is pinned. `pinOpenFiles` points every handle open on the path at the one copy, also a handle that holds an overlay file a reconcile removed, and reopens for writing a handle that holds the copy read-only. `Engine.pinOpenFiles` runs only while a handle is open on the path, and first calls `GrantOwnerAccess`, which lets a backing file an earlier version left read-only open for writing. `setPinnedAttributes` applies that setattr once per copy and keeps the copy's permission bits in `InodeRef.Mode`, where `heldAttrs` reads them.
- Record every entry reply with `allocEntry`, or with `createEntry` for a path the op created, and every attribute reply with `setReported`. `InvalidateChanged` compares what the kernel received, and any identity a reply replaced since the last pass, with the merged view. `allocEntry` drops the name's negative entry record. The exceptions are `GetInodeAttributes` for the root and the synthesized `.git` file, which `InvalidateChanged` skips, and a `GetInodeAttributes` or `SetInodeAttributes` reply from `heldAttrs`, which describes content no path shows.
- Record a lookup's reply, a negative entry too, only while the mount serves the generation the lookup resolved against, as `LookUpInode` does under `ArtifactFuse.mu`. Resolve again otherwise. The switch pass sends nothing for a reply recorded after it read the inode table and the negative entries.
- Log every entry reply and every attribute reply with `logReply`, the root, `.git` and `heldAttrs` replies too. Call it after the reply is set, holding no `ArtifactFuse.mu`. `logReply` checks the logger's level before it reads the path or builds the record, because lookups and getattrs call it on every reply.
- Prune snapshot generations only through `Service.pruneGenerations`, holding the runtime's `headMu` when it has one, so prunes record its kept generations one at a time. It never prunes the generation the runtime's resolver serves, which an activation can keep below its prune bound. An inode reads the generation of its last reported attributes, or a later one with the same identity, so a retired generation stays readable for `defaultGenerationRetention`.
- Read base content at `InodeRef.ReadGen`, never at `Gen`. The path has the identity last reported at `ReadGen`. `report` sets both fields. Only the switch pass advances `ReadGen`, for an inode it finds unchanged, and `mapLocked` sets it to the generation an unmapped inode's path came back at. Keep `report`'s ordering guard on `Gen`: a reply computed before the advance still reaches the kernel.
- `Engine.Identities` takes the identity of a mapped inode with a nonzero `ReadGen` as the base's at the inode's path at that generation. It resolves that path only when the path has its own overlay entry, when `Resolver.ChangedPaths` names the path, or when that diff fails or finds the generation pruned. It resolves every inode whose `ReadGen` is 0. It checks that a held directory with no overlay entries below it still exists. Set an inode's type, mode or blob only through `report`, which sets `Gen` and `ReadGen` with them. When an op makes a mapped inode's identity come from the overlay, or moves a mapped inode to another path, reset both to 0 in the same `ArtifactFuse.mu` hold, as `markWritten` and `moveInodePath` do. The switch pass resolves an unmapped inode's path with `Engine.IdentityAt`, not through `Engine.Identities`. `moveInodePath` keeps the generations of an unmapped inode it moves, because its open files read them. `mapLocked` sets the inode's `ReadGen` to the generation its path came back at when it maps back. `setPinnedAttributes` changes the mode of a retired inode, which the switch pass never compares.
- Publish only nodes that `BuildTreeIndex` returns. `Resolver.ChangedPaths` and `fusefs.SwitchedPaths` skip a directory whose tree ID both generations share, so a directory ID that is not its tree ID hides the changes below it.
- Keep every generation that `MountedFS.OpenFileGenerations` reports in each prune. An open handle without a descriptor of its blob opens it again at its inode's `ReadGen`. An open pins that generation with `pinInode` until `addFileHandle` registers its handle, in the same `ArtifactFuse.mu` hold, or the open fails. A run of the open that stops to hydrate carries its pin to the next run. Keep only the reported generations, not every one above the lowest.

## Writing tests

- Write a test to catch a regression, never to raise coverage. Do not add coverage targets.
- Make every regression test fail on the code before the fix. Revert the fix and watch the test fail.
- Drive behavior through the entry point real callers use, not an internal helper.
- Use real Git repositories in `t.TempDir()`. Fake the `git` binary only for what a local repository cannot produce: an HTTP error, a hang, a pause at one step, or a record of the arguments and environment git received.
- Build every new test on the real in-process stores in `t.TempDir()`: `overlay.New`, `snapshot.New` and `registry.New`. Fake a store only by wrapping a real one to inject a fault or a hook, as `faultyOverlay` and `hookedOverlay` do. A fake that reimplements a store tests the fake. `fakeSnapshot` and `generationSnapshot` in `internal/fusefs` reimplement the snapshot store. Only the tests that already use them may keep them.
- Assert the observable outcome: what `git status` reports, the resolved entry, or the persisted state. A nil error or a log line is not an outcome.
- Treat a log line, or the arguments and environment a fake git records, as the outcome only when it is the contract. `TestMountRepoLogsFuseErrorsRedacted` asserts the level and redaction of each fuse error record. `TestExistingCloneCredentialOperationsKeepCredentialsOutOfArguments` asserts that credentials reach git through its environment, never its arguments.
- Assert a result that only the code path under test produces. An unchanged index passes whichever check skips the bootstrap. `TestBootstrapCleanStatusIndexSkipsDeleteOnlyOverlay` therefore first bootstraps the same fixture without the overlay entry.
- Check the error of every setup call. A setup call that failed unseen makes an absence check pass with nothing to remove.
- Assert that an entry exists before you assert that it is gone. `TestReconcileAfterCommit` is the precedent.
- Assert the exact output, not only that a secret or an entry is gone. A redaction that blanks the whole remote, or a prune that deletes every generation, passes an absence check. `TestRedactRemoteURL` and `TestGenerationCleanup` are the precedents.
- When a test pins behavior that is a known bug, state the bug in the test's comment beside the assertion, so the fix flips that assertion.
- Call `gittest.IsolateConfig` from `TestMain` in every package whose tests run git. Prove it with a `TestGitIgnoresMachineConfig` that calls `gittest.RequireConfigIsolated`. The machine's global and system git config must not change a result. The root package keeps the machine config when `AFS_E2E_REPO` is set, so a real remote can authenticate through the ambient credential helper.
- Give each root-package `commit`, `commit-tree`, `merge`, `rebase` and annotated `tag` an identity, with `-c user.name=... -c user.email=...` or the repo's own config. `git stash` needs none, because it supplies its own fallback identity. The root package's `TestMain` sets `user.useConfigOnly` through `GIT_CONFIG_*`, also when `AFS_E2E_REPO` is set. Git then fails those calls without an identity instead of guessing one from the host. `TestGitCommitNeedsAConfiguredIdentity` proves the setting.
- The daemon sets `core.fsmonitor` to the hook link, a symlink to `os.Executable()`, or to the hook script, which execs `os.Executable()` with `fsmonitor-hook`. In a test, `os.Executable()` is the test binary. The root package's, `internal/daemon`'s and `internal/slimtree`'s `TestMain` answer both: a program name that `gitstore.ParseFSMonitorHookLink` accepts, and `fsmonitor-hook`. A test that replaces the hook link must remove it first: a write through it overwrites the test binary. Call `gittest.DisableRaceExitSleep` from each of those `TestMain`s. A race-built binary sleeps one second after it exits 0, so every git command that runs the hook would wait that second. Prove the call with a race-tagged `TestFSMonitorHookSkipsRaceExitSleep` that calls `gittest.RequireHookSkipsRaceExitSleep`. `internal/gitstore`'s `TestMain` calls `gittest.DisableRaceExitSleep` too, because git runs that test binary as SSH. There the call only saves time, so gitstore needs no `TestFSMonitorHookSkipsRaceExitSleep`.
- Never let a package test launch the real daemon program. slimtree starts the daemon from a copy of its own binary, which in a package test is the test binary. `internal/slimtree`'s `TestMain` makes `daemonProgram` fail, so give each test that reaches the launch `fakeDaemon`. That `TestMain` and `cmd/slimtree`'s exit 2 at once when the test binary runs as `daemon` or `afs`. A launch that slips through then fails, instead of running the tests again in the copy, which launches the next copy. `TestTestBinaryIsNotADaemon` pins the exit.
- Root the state of a test that expects the hook link in `gittest.PrivateTempDir(t)`. Under `t.TempDir()` on Linux, below `/tmp`, which every user can write, the hook is the script.
- Put every other test's state root in `gittest.StateRoot(t)`, or at a path below `t.TempDir()` that does not exist yet, which `ensureStateRoot` creates 0700. Under umask 002 `ensureStateRoot` refuses a bare `t.TempDir()`, because the group can write it.
- In a package whose `TestMain` does not answer the hook link and `fsmonitor-hook`, unset `core.fsmonitor` after a test installs the hook with `ConfigureFSMonitorHook` or `ConfigureStatusOptimization`. Unset it before any git command reads the index. Otherwise git runs the package's test binary as the hook, and that binary runs the package's tests again.
- In package tests, wait for an event, not for a fixed duration. Poll for the marker the fake git writes, and fail with the operation's error if it returns first. Receive from a hook that only a successful preparation of a `servedAsyncRepo` reaches with `receiveUnlessPrepareFails`, which fails the test once the preparation fails. Only `go test -timeout` bounds the wait. E2E tests keep bounded waits, because a timeout panic skips their unmount cleanup.
- Before a test asserts on `status`, wait until `repo_runtime` holds the write it expects. Poll `Controller.Status` until the result appears, or wait for a hook that runs after the write, such as `joinFinished`. Never poll `Service.records`: `recordRuntime` updates that copy before it writes `repo_runtime`.
- A daemon that `startDaemonWithMount` or `startService` starts never polls the registry. After a registry change, wake its sync loop with `wake`, as a CLI nudge does. Wake it once, after the step the sync depends on has finished, as `failConnection` does. Never wake it in a loop or set a short poll interval: a sync that lands inside a background step races that step.
- When a daemon test depends on when the HEAD watcher polls, send each poll through `Service.headPollTicks`. Never shorten the poll interval for it.
- Root the state of a daemon that a test starts in `shortTempDir`, not `t.TempDir()`. On macOS a `t.TempDir()` lies under `/var/folders`, so the control socket path exceeds sun_path's 104 bytes. The daemon then skips the socket, and a CLI nudge never wakes it. `startDaemonWithMount` and `newSyncedDaemon` already use `shortTempDir`.
- In `internal/daemon` and `internal/gitstore`, call `t.Parallel()` first in every test, and in every subtest that builds its own daemon or repository. Keep a test, and every test that contains it, serial when it calls `t.Setenv` or `t.Chdir`, directly or through a helper such as `gittest.IsolatePrompts`, `gittest.RequireConfigIsolated` or gitstore's `wrapGit`. gitstore runs the `git` on `PATH`, so a test that fakes git stays serial. Keep a test serial when it sets a package variable, such as `lstat`. Keep `TestRemovedRepoLeavesNoBatchProcess` serial, because it counts every `git cat-file --batch` child of the test process. Keep `TestFSMonitorHookSkipsRaceExitSleep` serial, because it bounds the hook's wall time, which parallel tests stretch.
- Bound every fake process that a regression would leave running, for example with `sleep 60`. A timeout panic skips cleanup, so an unbounded fake outlives the test. Detect the regression from the order of the fake's markers, not from how long it ran.
- Treat a flake as a product race until the failed run's log shows another cause. Find the interleaving the failure needs, pin it with a hook, and fix the product code. `TestPublishHoldsTheWriteLockFromItsGenerationRead` is the precedent: a SQLITE_BUSY flake was a read transaction's upgrade to a write.
- Read a failed attempt's log with `gh api --allow-escape-sequences repos/{owner}/{repo}/actions/jobs/<job id>/logs`. `gh run view --job <job id> --log` can return a later attempt's log instead.
- Expire a deadline under test with `gittest.ExpireOnFile` once the fake git reaches the step under test. A short timeout can expire in an earlier step on a loaded machine.
- Give a test's other git work `t.Context()`, never a wall-clock timeout. A loaded machine can expire the timeout mid-test.
- Never test a context check that precedes a git command with a context canceled before the call. `exec.Cmd.Start` returns the context's error itself, so the test passes with the check removed. Cancel once the fake git reaches the step under test, as `TestBuildTreeIndexPropagatesBatchCancellation` does.
- Pin an ordering of two operations with a hook at the step under test. Never loop hoping to hit the ordering. A loop pays for every iteration on every run and can still miss the window. `TestReadAcrossAFlushShowsCompletedWrites` is the precedent: the hooks in `internal/overlay/store.go` run a flush between a read's two reads, and a read between a flush's commit and its forget.
- Where a `model.*` interface seam exists, put the hook in a test type that implements the interface, as `hookedOverlay`, `pausingSnapshot` and `gatedHydrator` do. Where no seam exists, make the hook an unexported func variable or field that production code leaves nil. Never put a hook behind a build tag.
- A `-race` probe may loop. It runs two goroutines over shared state a bounded number of times, so the race detector sees an access outside the lock. Its assertions hold under every ordering; only the race detector fails it. `TestStopReadsTheConfigUnderTheLock` and `TestReadsCopyPendingWritesUnderTheLock` are the precedents.
- Test a change to how `meta.OpenDB` or `meta.Migrate` locks in `internal/meta`. There `TestOpenDBRetriesTheWALSwitch` commits a lock holder from a hook after the first switch to WAL failed, and `TestMigrateAppliesEachMigrationOnce` runs a second `Migrate` from a hook before the first takes the write lock. Each store's `TestConcurrentFirstOpensBuildTheSchema` opens the store concurrently once, and its opens need not overlap.
- Assert that something has not happened yet inside `synctest.Test`, after `synctest.Wait`. Drive ticker-based code there too. `synctest.Wait` does not treat a goroutine blocked on a `sync.Mutex` or a subprocess as idle, so those tests cannot use it.
- Where `synctest.Wait` cannot see a wait on a lock, test the lock directly. Check whether a lock is held at a step with `TryLock` from a hook at that step, as `lockProbeOverlay` does in `TestOverlayFileOpsHoldTransitionReadLock`. Assert that a goroutine waits on a lock with `waitParked` in `internal/fusefs`, as `TestInodeAndHandleCreationWaitForNamespaceMutation` does. `waitParked` matches frame names and a `Mutex` wait in the goroutine stacks. Change a function or lock type that a `waitParked` call names together with that call, or that call polls until `go test -timeout`.
- Never mount in a package test. Only the root-package e2e tests mount.
- Call an `Engine` method that takes a `*Blobs` through `Engine.Do`, as the FUSE adapter does. `internal/fusefs/ops_test.go` has `engineRename` and its siblings.
- Assert the errno the kernel receives with `kernelErrno`, not by comparing error values.
- Put a new decision that differs by platform in a file every platform builds, as `ownsLeftover` in `internal/daemon/mount.go` is. Take the platform as a parameter, as `ownsLeftover` takes `goos`. `TestOwnsLeftoverMatchesTheDaemonsMounts` then checks every platform's cases in `build-test` and in `darwin-test`. The constants and `platformMountConfig` in `internal/fusefs/fuse_darwin.go` and `fuse_linux.go`, and the path matching in `internal/daemon/mount_check_darwin.go`, may stay where they are. A test branch on `runtime.GOOS` runs only in that platform's CI job, as the darwin-only case of `TestMountPointHeld` runs only in `darwin-test`. Verify a change to such a branch in the job that runs it.
- A test can run as root: the `fuse-e2e (root)` job runs the e2e tests and one gitstore test under `sudo`, and a developer can run any test as root. `fuse-e2e (non-root)` mounts through the setuid `fusermount3`. Skip a test that expects a permission denial when it runs as root, because root ignores permission bits. `TestEvictCountsBlobsRemovedBeforeAFailedRemove` is the precedent. Skip a subtest that needs root when it runs as any other user. `build-test` and `darwin-test` run package tests without `sudo`. So add a step to the `fuse-e2e (root)` job that runs that subtest and fails without its PASS line, as the step for `TestSSHWrapperIsReusedOnlyWhilePrivate/directory_owner` does.
- In an e2e test, read and write mount files in a child process, with `readMountFile`, `writeMountFile`, `readMountFiles` or `readMountFilesUntil`, never through a file the test process holds open. The test process serves the mount. Since Linux commit e780259b54e6 ("exec: do_close_on_exec() before taking exec_update_lock"), a vfork child's exec closes its copy of each close-on-exec descriptor before it releases the parent, and closing a FUSE file sends FLUSH, which only the serving process answers. The forking thread holds its P with signals blocked, so GOMAXPROCS 1, a GC stop-the-world in that window, or every P forking at once deadlocks the mount. The server forks git to hydrate and prefetch, and the test forks git itself. Hold a mount file open in the test process only when the open file is the test's subject, and say so in a comment. Close it right after its last subject use, before the next fork. A directory descriptor sends no FLUSH, so it may stay in-process. `TestE2EMountPollingWithSingleProcessor` reads `.git` in-process, because its subject is the open's epoll registration, and opening `.git` forks nothing.
- In an e2e test, rename or open a path through the mount with `renameInMount` or `openatInMount`, never with a bare `unix.Rename` or `unix.Openat`. The mount answers an op that a signal interrupts while it waits for a blob to hydrate with EINTR, and changes nothing. Each helper retries that EINTR for at most `mountEINTRBound`, as the `os` functions retry it.
- Run a new e2e test as a `TestE2ESharedMount` subtest. Give it its own mount only when its subject is mounting, a daemon restart, or a fresh mount's state. Give a test its own mount also when it changes the mount and must run on FSKit, where `run` skips it. A test of an FSKit-only check that leaves the mount unchanged uses `runReadOnly` on the shared mount. macFUSE's FSKit extension can stop loading after a series of mounts in one session.
- Register a shared-mount test that leaves the mount unchanged with `runReadOnly`, and every other one with `run`. When e2e tests mount through FSKit on macOS, `run` skips the test, because the restore that undoes its changes moves HEAD. A `runReadOnly` test that changes the mount fails.
- Give every e2e daemon a logger from `newE2ELogger` or `newTestE2ELogger`. Both write warnings and errors to stderr, and every record from Debug up to a buffer. When a test fails, `logFuseRecords` prints the buffer's `fuse error`, `fuse entry reply` and `fuse attr reply` lines. `newTestE2ELogger` registers that call for its test. A `mountedE2ERepo` keeps its buffer in `logs`, and its cleanup and each shared-mount subtest call `logFuseRecords` on it. The fuse library logs the error behind an op's EIO at Debug, and the mount logs its replies there, so a Warn-level logger leaves an EIO with no daemon-side cause.
- Call `skipIfFSKitHEADMove` in a test that moves HEAD on its own mount. After a HEAD move, FSKit can pad a short read with bytes that are not file data ([macfuse#1231](https://github.com/macfuse/macfuse/issues/1231)).
- Before a test's first mount, call `skipIfOverMountBudget` with the number of mounts the test starts. A run that mounts through FSKit starts at most 8 mounts. `newMountedE2ERepo` checks one mount.

## Validation

- Start with the narrowest relevant test: `go test ./internal/<pkg>` or `go test -run TestName ./internal/<pkg>`.
- For non-trivial code changes, reproduce CI in order: `go run golang.org/x/tools/go/analysis/passes/modernize/cmd/modernize@v0.52.0 -fix ./...` with no resulting diff, `go build -o /dev/null ./cmd/artifact-fs ./cmd/slimtree`, `go vet ./...` with `GOOS=linux` and with `GOOS=darwin`, then `go test -race -count=1 ./...`.
- Build only the binaries with `go build -o . ./cmd/artifact-fs ./cmd/slimtree`. Without `-o`, `go build` of more than one package writes no binary.
- Enable the pre-commit checks with `git config core.hooksPath .githooks`.
- Benchmarks are opt-in: `AFS_RUN_BENCH=1 go test -run TestBenchRepos -v`.
- FUSE e2e tests are opt-in. Run them with the same command on macOS and Linux: `AFS_RUN_E2E_TESTS=1 go test -run 'TestE2E|TestFUSEMountSmoke' -count=1 -timeout 20m -v .`. Keep `-timeout 20m`: the default 10m can expire mid-suite, and a timeout panic skips every unmount cleanup. `TestE2ESlimtreeLifecycle` drives the slimtree binary that `AFS_E2E_SLIMTREE` names, else one it builds with `go build`. The `fuse-e2e` job builds it, because the root run has no `go` on `PATH`.
- On Linux, e2e tests need `/dev/fuse` plus either root or `fusermount3` from the `fuse3` package. Unmount a leftover mount with `fusermount3 -u <path>`, or `fusermount3 -uz <path>` when it hangs.
- On macOS, e2e tests mount through FSKit. Set `ARTIFACT_FS_FUSE_BACKEND=kernel` only to test the macFUSE kernel extension; without a loaded kernel extension those tests skip. Unmount a leftover FSKit mount with `diskutil unmount <path>`. A deadlocked FSKit mount cannot be unmounted until reboot.
- E2E tests use a local bare repository by default. Set `AFS_E2E_REPO` only when intentionally testing a real remote.
- E2E benchmark coverage is separate: `AFS_RUN_E2E_BENCH=1 go test -run TestE2EBenchmarkRepos -v .`.
- Package tests and `Benchmark*` functions live beside the code. `TestBenchRepos`, `TestE2EBenchmarkRepos` and every `e2e*_test.go` live in the root package.
